# Single Live Release Hub

A unified release tracking portal that pulls from **two separate Jira instances**, links pre-release notes (Google Docs) and presentations (Google Slides), and sends a monthly executive digest.

## How It Works

```
┌─────────────────┐     ┌─────────────────┐
│  Jira Instance  │     │  Jira Instance  │
│   (Company A)   │     │   (Company B)   │
└────────┬────────┘     └────────┬────────┘
         │    Fix Versions + Issues    │
         └─────────────┬───────────────┘
                       ▼
              ┌────────────────┐
              │   jira-sync    │  ← merges in Google Docs/Slides links
              └────────┬───────┘
                       ▼
              ┌────────────────┐
              │ releases.json  │  ← single source of truth
              └───┬────────┬───┘
                  │        │
         ┌────────┘        └────────┐
         ▼                          ▼
┌─────────────────┐      ┌──────────────────┐
│   Release Hub   │      │  Monthly Digest  │
│   (HTML page)   │      │  (email on 1st)  │
└─────────────────┘      └──────────────────┘
```

## Quick Start

```bash
# Install dependencies
npm install

# Preview the hub with sample data (no Jira credentials needed)
npm run serve
# → Open http://localhost:3000

# Preview the monthly digest
npm run digest:preview
```

## Setup

### 1. Configure Jira Instances

Copy the environment file and fill in your credentials:

```bash
cp .env.example .env
```

Edit `.env` with your Jira API tokens (generate at https://id.atlassian.com/manage-profile/security/api-tokens):

```
JIRA_COMPANY_A_EMAIL=your-email@company-a.com
JIRA_COMPANY_A_TOKEN=your-api-token
JIRA_COMPANY_B_EMAIL=your-email@company-b.com
JIRA_COMPANY_B_TOKEN=your-api-token
```

Then update `config/jira.config.json` with your actual:
- Instance base URLs
- Project keys
- Any additional JQL filters

### 2. Sync Releases from Jira

```bash
# Dry run (preview what would be synced)
npm run sync:dry

# Full sync (writes to data/releases.json)
npm run sync
```

The sync pulls all non-archived Fix Versions from configured projects and categorizes them:
- **Upcoming** = unreleased Fix Versions
- **Published** = released Fix Versions

### 3. Link Google Docs and Slides

Edit `data/release-assets.json` to attach documents to releases:

```json
{
  "company-a_10201": {
    "preReleaseNotes": {
      "url": "https://docs.google.com/document/d/YOUR_DOC_ID/edit",
      "docId": "YOUR_DOC_ID",
      "title": "v2.4.0 - Pre-Release Notes"
    },
    "presentation": {
      "url": "https://docs.google.com/presentation/d/YOUR_SLIDES_ID/edit",
      "presentationId": "YOUR_SLIDES_ID",
      "title": "v2.4.0 - Release Presentation"
    },
    "additionalLinks": [],
    "highlights": [
      "Key feature or change for the digest"
    ],
    "tags": ["major", "payments"]
  }
}
```

The key format is `{company-id}_{jira-version-id}` — you can find the version ID in the Jira URL when viewing a Fix Version.

Google Docs and Slides are embedded inline in the hub (click to preview without leaving the page). Ensure sharing is set to "Anyone with the link can view" for embedding to work.

### 4. Serve the Hub

```bash
npm run serve
```

The hub page loads `data/releases.json` (live synced data) and falls back to `data/releases.sample.json` if no sync has run yet.

## Monthly Executive Digest

The digest is generated on the 1st of each month and summarizes:
- All releases shipped in the previous month (grouped by company)
- Key upcoming milestones in the next 30 days
- High-level stats (total releases, features, bug fixes)

### Generate

```bash
# Generate digest for previous month → outputs to dist/
npm run digest

# Preview in terminal
npm run digest:preview

# Generate for a specific month (e.g., July)
node src/generate-digest.js --month 7
```

### Schedule (cron)

To automatically send the digest on the 1st of every month:

```cron
0 8 1 * * cd /path/to/release-hub && npm run sync && npm run digest
```

## Workflow

1. **Sync runs hourly** (or on-demand) pulling the latest Fix Versions from both Jira instances
2. **Asset links are maintained** in `data/release-assets.json` — add your Google Doc / Slides URLs when you create them for a release
3. **The hub updates automatically** — it reads the latest `releases.json` on page load
4. **On the 1st of each month**, the digest script generates and sends the executive summary email

## Customization

### Adding more Jira instances

Add another entry to the `instances` array in `config/jira.config.json`. The sync script handles any number of instances.

### Changing company colors

Edit the CSS variables at the top of `public/index.html`:

```css
--color-company-a: #6366f1;
--color-company-b: #f59e0b;
```

### Modifying the digest template

Edit `templates/digest-email.hbs`. It uses Handlebars with these helpers:
- `{{formatDate dateStr}}` — "Aug 3, 2026"
- `{{shortDate dateStr}}` — "Aug 3"
- `{{pluralize count "word" "words"}}`
- `{{tagClass tagName}}` — returns CSS class for a tag

### Adding tags

Tags are free-form strings in `release-assets.json`. The hub and digest both display them. Suggested conventions:
- `major` — significant feature releases
- `hotfix` — emergency fixes
- `security` — security-related changes
- `infrastructure` — backend/ops changes
